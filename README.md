# 棚卸しカウンター (Inventory Count App)

カメラで対象物を映すだけで「何が」「何個」あるかを数え、棚卸し記録として残すアプリです。
ワインの棚卸しを主な用途として想定しており、「ボトルが何本」ではなく「どの銘柄が何本」まで
識別・記録できることを目標にしています。

ブラウザ（PWA）として作られているため、MacBook Air / iPhone / Rokid グラス（Android系ブラウザ）
など、カメラ付きのデバイスであれば追加インストールなしで動作します。

## 構成

```
server/   Node.js + Express + SQLite の API サーバー
client/   Vite + React によるフロントエンド (PWA)
```

- **一般物体カウントモード**: TensorFlow.js (COCO-SSD) をブラウザ内でロードし、カメラ映像から
  リアルタイムに物体を検出してクラスごとにカウントします（完全にオンデバイス処理）。
- **ワインモード**: ラベルを撮影 → Tesseract.js による OCR でラベルの文字を読み取り →
  既存の棚卸し表（マスタ）とあいまい照合 → 候補を提示し、人が確認してから記録します。
  一致しない場合はオンライン検索、または手動入力で新規銘柄として登録します。
- **フォーマット自動判定**: 既存の棚卸し表（.xlsx / .csv）をアップロードすると、列名から
  「銘柄」「数量」等の役割を自動判定し、そのフォーマットに準拠して記録・エクスポートします。
  判定できない場合は独自フォーマットを新規作成します。

## なぜこの設計か

- **ワインは「見た目が同じでも銘柄が違う」**: 汎用物体検出（COCO-SSD）は「ボトル」としてしか
  認識できず、銘柄までは分かりません。そこでワインだけは撮影 → OCR → 照合という別フローにし、
  ヴィンテージ（年号）や細かい文字の違いを OCR テキストとして残し、あいまい照合でも
  年号が食い違う候補は自動的にスコアを下げるようにしています（`server/src/services/wineMatcher.ts`）。
  さらに最終判断は必ず人間の確認を挟みます（自動確定はしません）。OCR結果はテキストボックスで
  修正してから照合し直せます。
- **既存の棚卸し表を壊さない**: 既存フォーマットを検出した場合、元の行データ (`raw`) を保持し、
  エクスポート時に数量列だけ更新して他の列はそのまま書き戻します。

## セットアップ

### 必要なもの: Node.js 20 か 22（LTS）

`better-sqlite3` など一部のライブラリはNode.jsの最新版（非LTS）向けの事前ビルド済みバイナリが
間に合っておらず、ソースからのコンパイルに失敗することがあります。
[nvm](https://github.com/nvm-sh/nvm) で安定版（LTS）のNode.jsを使うことを強く推奨します。

```bash
node -v
```

`v20.19.x` 系か `v22.12.x` 以降でなければ、nvmを入れて切り替えてください。

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
```

一度ターミナルを閉じて開き直してから、

```bash
nvm install 22
nvm use 22
node -v
```

`v22.x.x` になっていればOKです（以降、新しいターミナルを開くたびに `nvm use 22` が必要な場合があります）。

### 依存パッケージのインストール

以前に一部だけインストールが失敗している場合は、念のため一度消してからやり直してください。

```bash
rm -rf node_modules server/node_modules client/node_modules package-lock.json
```

サーバーとクライアント、それぞれ**1行ずつ順番に**実行し、途中でエラーが出ていないか確認してください
（`&&` で繋いで一気に実行すると、片方が失敗したときにもう片方が実行されず、原因が分かりにくくなります）。

```bash
npm install --workspace server
```

```bash
npm install --workspace client
```

### サーバー起動とクライアント起動（別々のターミナルで）

`dev:server` と `dev:client` はどちらも「動き続けるプロセス」なので、**ターミナルのウィンドウ/タブを2つ**
開いて、それぞれ別々に実行してください（1つのターミナルで順番に実行すると、1つ目が終わらないので
2つ目が永遠に始まりません）。

ターミナル①:

```bash
npm run dev:server
```

`http://localhost:3001` で待受を始めます。

ターミナル②（新しいタブ/ウィンドウを開いて）:

```bash
npm run dev:client
```

`http://localhost:5173` が使えるようになります（`/api` はターミナル①のサーバーへ自動的に転送されます）。

MacBook Air自身のブラウザで使うだけなら、ここまでで完了です（`http://localhost:5173` を開く）。

### iPhone / Rokidグラスなど、他のデバイスから使う場合

ブラウザのカメラAPIは HTTPS（または `localhost`）でしか動作しません。同じWi-Fi内の
別デバイスからLAN経由でアクセスする場合は、[mkcert](https://github.com/FiloSottile/mkcert) で
ローカル用のHTTPS証明書を発行してください（初回のみ）。

```bash
brew install mkcert nss   # 未インストールの場合
cd client
npm run certs             # .certs/ に証明書を生成し、Macの信頼済みCAに登録
```

その後 `npm run dev:client` を実行すると自動的に **https://** で起動し、ターミナルに

```
➜  Network: https://192.168.x.x:5173/
```

のようなURLが表示されます。これを同じWi-FiにつないだiPhoneのSafariやRokidグラスの
ブラウザで開けば、カメラが使えます。

初回アクセス時は証明書が「未信頼」の警告が出ることがあります。警告なしで使いたい場合は、
`npm run certs` 実行時に表示される `rootCA.pem` を各デバイスに転送し、信頼済みルート証明書として
インストールしてください（iPhoneはAirDrop→設定アプリでプロファイルインストール→
証明書信頼設定で完全信頼をON、Rokid(Android)は設定→セキュリティ→CA証明書のインストール）。

### ビルド / テスト

```bash
npm run build   # server (tsc) + client (tsc + vite build)
npm run test    # server (vitest) + client (vitest)
```

## オンラインワイン検索の設定（任意）

OCR結果が既存棚卸し表に見つからない場合、オンライン検索で銘柄の手がかりを探せます。
デフォルトではプロバイダ未設定のため「設定されていません」と表示されるだけです。
Google Programmable Search Engine を使う場合は、サーバー起動時に以下の環境変数を設定してください。

```bash
GOOGLE_CSE_API_KEY=xxxx GOOGLE_CSE_CX=xxxx npm run dev:server
```

他の検索/ワインDBサービスを使いたい場合は `server/src/services/wineLookup.ts` の
`WineLookupProvider` インターフェースを実装して差し替えられます。

## 使い方の流れ（ワイン棚卸し）

1. 「棚卸し表・記録」タブで既存の棚卸し表（.xlsx / .csv）をアップロード（任意）。
   - 列名から自動でフォーマットを認識します（例: 銘柄/商品名/Name, 数量/Qty, ヴィンテージ/Vintage 等）。
   - 認識できなければ独自フォーマット（銘柄・生産者・ヴィンテージ・種別・数量・場所・備考）で新規作成されます。
2. 「ワインモード」タブでカメラを起動し、ラベルを撮影。
3. OCRで読み取った文字を確認・修正し、「既存棚卸し表と照合」。
4. 候補が出たら一致するものを選んで本数を記録。見つからなければオンライン検索または
   手動入力で新規銘柄として登録（次回以降はマスタに載るので照合対象になります）。
5. 「棚卸し表・記録」タブの「Excelでエクスポート」から結果を出力。

「一般物体カウント」タブは、箱・カップ・本など銘柄を問わない一般的な物のリアルタイムカウントに使えます。

## トラブルシューティング

- **`npm install` が `better-sqlite3` のビルドで失敗する / `node-gyp` のエラーが出る**
  → 上記の「必要なもの: Node.js 20 か 22（LTS）」を参照し、nvmでLTS版に切り替えてから
  `rm -rf node_modules server/node_modules client/node_modules package-lock.json` で
  一度クリーンにしてインストールし直してください。
  それでも失敗する場合はXcodeのコマンドラインツールが必要です: `xcode-select --install`
- **`sh: tsx: command not found` / `Cannot find module 'tesseract.js/package.json'`**
  → 依存パッケージのインストールが（多くは直前の `better-sqlite3` のビルド失敗で連鎖的に）
  完了していません。上記のクリーンインストール手順をやり直してください。
- **ブラウザで `localhost:5173` に接続拒否 (ERR_CONNECTION_REFUSED)**
  → `npm run dev:client` がエラーで落ちている（起動できていない）ことがほとんどです。
  ターミナル②の画面に赤いエラーが出ていないか確認してください。
- **iPhone/Rokidグラスでカメラが起動しない**
  → `http://` の LAN アドレスではブラウザのカメラAPIがブロックされます。
  「iPhone / Rokidグラスなど、他のデバイスから使う場合」の手順で `https://` にしてください。

## 既知の制限・今後の拡張ポイント

- **リアルタイムのワイン銘柄認識**: 現状は撮影→OCRの静止画フローです。継続的なリアルタイム銘柄認識には
  カスタム学習済みモデルや商用の画像認識APIが必要になるため、`WineLookupProvider` と同様に
  差し替え可能な設計にしてあります。
- **OCR精度**: Tesseract.js (`eng+jpn`) を使用しています。フランス語/イタリア語などのワインラベルは
  英語モデルでもある程度読めますが完全ではありません。読み取り結果は必ず画面上で確認・修正できます。
- **COCO-SSDの分類粒度**: 「ボトル」「カップ」等80クラスの一般物体分類までで、商品固有の識別はできません。
- **オフライン利用**: OCR言語データ・COCO-SSDのモデル重みは初回のみCDNからダウンロードされます
  （Tesseractのワーカー本体とWASMコアはアプリに同梱してCDN依存を無くしています）。
  ネットワークが閉域の環境で使う場合は、言語データ・モデル重みも社内サーバー等に配置し、
  `useOCR.ts` / `useObjectDetector.ts` のパスを差し替えてください。
